# Analysis Modules

## Module 1: Trigger Triage

### Purpose

Determine whether an event is research-worthy.

### Inputs

```text
news
filing
earnings call
policy
price action
company announcement
industry data
user observation
```

### Output

```text
Trigger Type
Affected Direction
First-order Beneficiaries
Second-order Beneficiaries
Potential Losers
Real Variable Changed?
Priority
```

### Priority Levels

```text
Ignore
Watch
Deep Dive
Thesis Candidate
```

---

## Module 2: Problem Definition

### Purpose

Prevent concept-driven research.

### Output Pattern

```text
The direction exists because ______ is expensive / scarce / slow / risky / underpenetrated.
The buyer pays because ______.
The measurable improvement is ______.
```

### Problem Quality Test

Score each from 0–2:

```text
Urgency
Recurring nature
Budget owner clarity
Measurability
Switching incentive
```

Maximum: 10.

## Module 5: Commoditization Risk

### Purpose

Avoid confusing revenue growth with value capture.

### Red Flags

```text
customer self-build
open-source pressure
low switching cost
standardized product
many suppliers
government-subsidized capacity
declining ASP
inventory build
```

### Output

```text
Layer at risk
Why
Timeline
Survivors
Investment implication
```

## Module 7: Variant Perception

### Purpose

Generate a differentiated, testable thesis.

### Valid Variant Forms

```text
Right direction, wrong layer.
Right demand, wrong margin.
Right winner, wrong timing.
Right near-term, wrong durability.
Obvious beneficiary is crowded; second-order beneficiary is underpriced.
Market sees revenue; misses working-capital or margin risk.
Market sees technology; misses customer adoption friction.
```

### Output

```text
Consensus
Variant view
Why the gap exists
Evidence required
Falsification
```

## Module 10: Memo Composer

### Purpose

Write the final output in a concise buy-side style.

### Rules

```text
Use direct language.
Avoid generic optimism.
Separate facts and assumptions.
State uncertainty.
End with next steps.
```
